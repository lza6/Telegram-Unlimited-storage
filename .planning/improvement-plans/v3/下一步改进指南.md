## 3. 性能深度优化（P1 — 第2-3周）

### 3.1 [V3-05] SQLite 异步化 + 连接池

**当前状态**: `storage.py` 使用 `threading.RLock()` + 单连接，所有操作串行。

**问题根因**: 高并发时多个请求排队等锁，P99 延迟飙升。

**执行方案**:
```python
# 方案：aiosqlite + asyncio.Lock（读并发 + 写串行）
import aiosqlite

class AsyncStorage:
    def __init__(self, db_path: Path):
        self._db_path = db_path
        self._write_lock = asyncio.Lock()
        self._conn: Optional[aiosqlite.Connection] = None

    async def _get_conn(self) -> aiosqlite.Connection:
        if self._conn is None:
            self._conn = await aiosqlite.connect(str(self._db_path))
            await self._conn.execute("PRAGMA journal_mode=WAL")
            await self._conn.execute("PRAGMA foreign_keys=ON")
            self._conn.row_factory = aiosqlite.Row
        return self._conn

    async def _query(self, sql: str, params=()) -> list[dict]:
        conn = await self._get_conn()
        cursor = await conn.execute(sql, params)
        rows = await cursor.fetchall()
        return [dict(row) for row in rows]

    async def _execute(self, sql: str, params=()) -> int:
        async with self._write_lock:
            conn = await self._get_conn()
            cursor = await conn.execute(sql, params)
            await conn.commit()
            return cursor.rowcount
```

**注意**: 不需要完全重写 `Storage` 类，可以渐进式迁移：
1. 新建 `AsyncStorage` 类，保留原 `Storage` 作为兼容
2. 逐步将路由切换到 `AsyncStorage`
3. 最终移除 `Storage` 类

**验收标准**:
- [ ] 读操作并发无锁
- [ ] 写操作正确串行化
- [ ] 并发读取吞吐量提升 3x+
- [ ] 所有现有测试通过（或使用适配器）

### 4.4 [V3-13] 请求频率限制增强

**当前状态**: 仅有 IP 级别滑动窗口，无 API Key 级别限制。

**执行方案**:
```python
class TieredRateLimiter:
    def __init__(self):
        self._ip_limiter = SlidingWindowRateLimiter(120)  # IP: 120/min
        self._api_limiter = SlidingWindowRateLimiter(300)  # API Key: 300/min

    def allow(self, request: Request) -> tuple[bool, int]:
        ip = _client_ip(request)
        api_key = request.headers.get("X-API-Key")
        # IP 级别
        ip_ok, ip_retry = self._ip_limiter.allow(ip)
        if not ip_ok:
            return False, ip_retry
        # API Key 级别（如果有）
        if api_key:
            api_ok, api_retry = self._api_limiter.allow(api_key)
            if not api_ok:
                return False, api_retry
        return True, 0
```

**验收标准**:
- [ ] IP 和 API Key 双重限制
- [ ] 不同端点可配置不同限制
- [ ] 速率限制指标可通过 /metrics 查看

### 10.1 [V3-34] 静态资源哈希化 + 打包

**当前状态**: 静态文件无版本控制，浏览器缓存策略困难。

**执行方案**:
```javascript
// 使用简单的构建脚本
// scripts/build-web.js
const fs = require('fs');
const crypto = require('crypto');
const path = require('path');

const assetsDir = path.join(__dirname, '../deploy/web/assets');
const files = fs.readdirSync(assetsDir).filter(f => f.endsWith('.js') || f.endsWith('.css'));

const manifest = {};
for (const file of files) {
    const content = fs.readFileSync(path.join(assetsDir, file));
    const hash = crypto.createHash('md5').update(content).digest('hex').slice(0, 8);
    const ext = path.extname(file);
    const base = path.basename(file, ext);
    const hashedName = `${base}.${hash}${ext}`;
    fs.copyFileSync(
        path.join(assetsDir, file),
        path.join(assetsDir, 'hashed', hashedName)
    );
    manifest[file] = hashedName;
}
fs.writeFileSync(
    path.join(assetsDir, 'hashed', 'manifest.json'),
    JSON.stringify(manifest, null, 2)
);
```

## 13. 技术选型建议（v3 新增）

| 领域 | 推荐方案 | 理由 |
|------|----------|------|
| 前端 SPA | htmx 1.9+ | 最小改动，保持静态部署 |
| 异步数据库 | aiosqlite | 渐进式迁移，兼容现有 SQL |
| 全文搜索 | SQLite FTS5 | 零依赖，性能足够 |
| 结构化日志 | structlog | Python 生态标准 |
| 分布式追踪 | OpenTelemetry | 行业标准，可选启用 |
| 流式 ZIP | Python zipfile + 流式 | 标准库，零依赖 |
| 前端构建 | 简单 Node.js 脚本 | 不需要 Webpack/Vite |
| 容器化 | 多阶段 Dockerfile | 减小镜像体积 |
