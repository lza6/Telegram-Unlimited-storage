## 1. 安全与合规强化

### 1.1 密码哈希KDF升级 (P0)

**需确认当前状态**:
- 检查 `auth_routes.rs` 和 `share_routes.rs` 中密码哈希实现
- 若仍为SHA256单轮: 升级为Argon2id

**实施**:
```rust
// 若需升级
use argon2::{Algorithm, Argon2, Params, Version};

fn hash_password(password: &str, salt: &[u8]) -> Result<[u8; 32], argon2::Error> {
    let params = Params::new(65536, 3, 4, None)?;
    let argon2 = Argon2::new(Algorithm::Argon2id, Version::V0x13, params);
    let mut output = [0u8; 32];
    argon2.hash_password_into(password.as_bytes(), salt, &mut output)?;
    Ok(output)
}
```

**验证步骤**:
1. 阅读密码哈希当前实现
2. 如已使用KDF则跳过
3. 如使用SHA256: 添加argon2依赖 + 渐进迁移 + 向后兼容

### 1.2 unwrap() 审计与消除 (P0)

**检查清单**:
```
fs.rs:     client_opt.unwrap() × N
vpn_opt:   self.vpn.read().unwrap() × N
auth.rs:   mutex lock unwrap × N
api_routes: StatusCode.unwrap()
```

**策略**: 创建 `get_client_safe()`, `safe_lock()` 辅助函数

### 1.3 Mutex在异步上下文的审计 (P1)

**检查所有**:
- `std::sync::Mutex` → 仅在不阻塞场景使用
- `std::sync::RwLock` → 考虑迁移到 `tokio::sync::RwLock`
- 短临界区可保留 `std::sync::Mutex` (规范)

### 1.4 多租户安全审查 (P1)

**检查项**:
- 租户隔离是否严格 (租户A不能访问租户B文件)
- API Key轮换机制
- 租户数据清理

### 1.5 HMAC预签名安全 (P1)

**检查项**:
- `DOWNLOAD_SIGNING_SECRET` 强度要求 (≥32字符)
- 签名算法: HMAC-SHA256
- 过期验证准确性

### 1.6 安全头部完整性 (P2)

| 头部 | 状态 | 建议 |
|------|------|------|
| HSTS | ⚠️ 确认 | 确认 max-age 配置 |
| CSP | ⚠️ 确认 | 确认是否支持nonce |
| XFO | ⚠️ 确认 | DENY |
| Permissions-Policy | ⚠️ 确认 | 相机/麦克风/定位禁用 |
