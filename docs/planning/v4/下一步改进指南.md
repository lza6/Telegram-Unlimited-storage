## 1. 项目基线与 v3 成果深度诊断

### 1.1 当前代码资产与技术深度评估
- **后端架构**: FastAPI 作为 REST API 骨架，通过 Telethon 使用 MTProto 协议直接与 Telegram 通信，设计了 Bot API 和 User 模式双轨道。
- **存储机制**: 当前仅有同步的 `Storage` 实例，利用 `threading.RLock()` 对 SQLite 的写操作加锁以避免“Database is locked”异常，而读操作利用 `thread-local` 生成多个连接并发读取。这种设计虽然在单实例、低并发下性能尚可，但在多实例部署和密集 I/O 情况下存在线程切换开销、写锁独占导致的请求排队饥饿，且完全无法支持云原生水平扩展。
- **孤岛模块状态**:
  - `errors.py`: 已实现了 8 种高内聚结构化异常类（如 `NotFoundError`, `PayloadTooLargeError`），但各个路由端点仍保留着零散的 `api_error()` 字符串返回，未完全闭环。
  - `metrics.py`: 设计了 Prometheus 监控指标，但未实现全局中间件捕获和 `/metrics` 端点注册。
  - `upload-drop.js` & `notifications.js`: 存在但在多页面中属于临时或散落的引用，未做到全局前端资产的原子化注入。

### 1.2 企业级瓶颈（从单实例到分布式集群）
- **状态不透明**: 传输进度 `ProgressBus` 依赖内存状态，多机部署时无法同步。
- **限流单机化**: 滑动窗口限流基于单机内存中的 dict，无法防范跨节点的 DDOS 与并发抢占。
- **搜索效能低**: 模糊搜索使用 SQL `LIKE` 子句，数据量破万时索引失效，且不支持拼音/拼音首字母模糊匹配。
- **缺乏双轨数据库**: 缺乏将边缘环境（轻量 SQLite）与云端 SaaS 控制面环境（PostgreSQL）灵活切换的中间 Repository 抽象。

## 2. 闭环集成任务 (P0 - 第1周)

### 2.1 结构化异常全局映射
在 `backend/app/main.py` 中移除旧的异常抓取逻辑，接入 `errors.py` 全局 Exception Handler。

```python
# app/main.py
from app.errors import TelegramDriveError

@app.exception_handler(TelegramDriveError)
async def telegram_drive_exception_handler(request: Request, exc: TelegramDriveError):
    logger.warning(
        "api_error",
        code=exc.code,
        message=exc.message,
        status_code=exc.status_code,
        request_id=getattr(request.state, "request_id", None)
    )
    return JSONResponse(
        status_code=exc.status_code,
        content=exc.as_dict()
    )
```

**路由层重构规范**:
- 在 `routers/files.py`、`routers/shares.py`、`routers/webdav.py` 中，禁止直接 return `{"error": ...}`，一律通过 `raise ValidationError("error_msg")` 或 `raise NotFoundError("file", file_id)` 抛出异常。

### 2.2 Prometheus Metrics 接入与动态轮询
在路由中注册 `/metrics` 并通过 HTTP 校验保护。同时，将 Prometheus Collector 与 FastAPI 中间件结合：

```python
# app/routers/health.py
from app.metrics import get_metrics

@router.get("/metrics", tags=["monitoring"])
async def metrics(request: Request, x_metrics_token: Optional[str] = Header(None)):
    settings = request.app.state.settings
    if settings.metrics_token and x_metrics_token != settings.metrics_token:
        raise AuthenticationError("Invalid metrics token")
    return Response(content=get_metrics(), media_type="text/plain")
```

## 3. 安全加固 (P1 - 第2-3周)

### 3.1 下载预签名 URL 密钥多级轮换机制
签名链接（`links.py`）容易因为单一密钥泄露而被迫让所有已签发的 URL 彻底失效。本机制引入多级轮换支持：

```python
# app/security.py
import itsdangerous
from itsdangerous import SignatureExpired, BadSignature

def sign_url(payload: dict, secrets: list[str], key_id: int = 0) -> str:
    """使用 list 中的首个 active 密钥进行签名，并将 key_id 写入 token 头部"""
    serializer = itsdangerous.URLSafeSerializer(secrets[key_id])
    token = serializer.dumps(payload)
    return f"v4.{key_id}.{token}"

def unsign_url(token_str: str, secrets: list[str]) -> dict:
    """解析 v4.[key_id].[token] 结构并遍历对应密钥解密，支持平滑过渡"""
    if not token_str.startswith("v4."):
        raise BadSignature("Invalid token format")
    parts = token_str.split(".", 2)
    key_id = int(parts[1])
    token = parts[2]
    
    if key_id >= len(secrets):
        raise BadSignature("Key ID out of range")
        
    serializer = itsdangerous.URLSafeSerializer(secrets[key_id])
    return serializer.loads(token)
```

### 3.2 WebDAV 暴力破解 AccessGuard 融合
WebDAV 协议使用 HTTP Basic Auth，企业级架构下极易遭受撞库攻击。必须将 WebDAV 认证失败事件与 `AccessGuard` 彻底打通：

```python
# app/routers/webdav.py
@router.api_route("/{path:path}", methods=["PROPFIND", "GET", "PUT", "DELETE"])
async def handle_webdav(request: Request):
    state = request.app.state.app
    client_ip = request.client.host
    
    # 每次请求先过防爆锁
    state.authenticator.guard.check(client_ip)
    
    # 验证逻辑...
    if not authenticated:
        state.authenticator.guard.record_failure(client_ip)
        raise HTTPException(status_code=401, headers={"WWW-Authenticate": 'Basic realm="WebDAV"'})
```

## 4. 高并发与分布式就绪 (P1 - 第4-5周)

### 4.1 aiosqlite 异步与连接隔离
替换同步的 `sqlite3` 数据库读写器，构建 `aiosqlite` 连接管理层，支持读写连接分离：

```python
# app/storage.py
import aiosqlite

class AsyncStorage:
    def __init__(self, db_path: str):
        self.db_path = db_path
        self._write_lock = asyncio.Lock()

    async def get_read_conn(self) -> aiosqlite.Connection:
        # WAL 模式支持多读并发
        conn = await aiosqlite.connect(self.db_path)
        await conn.execute("PRAGMA journal_mode=WAL")
        await conn.execute("PRAGMA query_only=ON")
        conn.row_factory = aiosqlite.Row
        return conn

    async def execute_write(self, sql: str, params: tuple = ()) -> int:
        async with self._write_lock:
            async with aiosqlite.connect(self.db_path) as conn:
                await conn.execute("PRAGMA journal_mode=WAL")
                async with conn.execute(sql, params) as cursor:
                    await conn.commit()
                    return cursor.rowcount
```

### 4.3 Redis 分布式系统网关
当配置启用 Redis 后，单实例的内存缓存和限流将平滑升级为基于 Redis 的全局组件：

```python
# app/redis_limiter.py
import time

class RedisSlidingWindowRateLimiter:
    def __init__(self, redis_client, limit: int, window: int = 60):
        self.redis = redis_client
        self.limit = limit
        self.window = window

    async def is_allowed(self, key: str) -> tuple[bool, int]:
        now = time.time()
        clear_before = now - self.window
        pipeline = self.redis.pipeline()
        pipeline.zremrangebyscore(key, 0, clear_before)
        pipeline.zadd(key, {str(now): now})
        pipeline.zcard(key)
        pipeline.expire(key, self.window)
        _, _, count, _ = await pipeline.execute()
        
        if count > self.limit:
            return False, int(self.window - (now - clear_before))
        return True, 0
```

## 5. AI 原生与元数据引擎 (P2 - 第6周)

### 5.1 FTS5 拼音全文检索设计
基于 SQLite FTS5 构建文件名拼音首字母（如 `xlkj` 匹配 `寻雷科技`）的多模态极速模糊搜索：

```sql
-- 创建全文检索虚拟表
CREATE VIRTUAL TABLE IF NOT EXISTS file_fts USING fts5(
    message_id,
    file_name,
    pinyin_full,
    pinyin_abbr,
    content='file_assets',
    tokenize='porter unicode61'
);

-- 同步触发器
CREATE TRIGGER IF NOT EXISTS tg_file_assets_insert AFTER INSERT ON file_assets BEGIN
    INSERT INTO file_fts(rowid, message_id, file_name, pinyin_full, pinyin_abbr)
    VALUES (new.rowid, new.message_id, new.file_name, new.pinyin_full, new.pinyin_abbr);
END;
```

### 5.2 智能分类与文件消重哈希
- **分类算法**: 在上传文件的元数据流通过时，利用自定义特征匹配（魔数 + 文件尾签名验证），将文件自动打上：`图片/视频/文档/压缩包/源码/其他` 标签。
- **秒传消重机制**: 分片上传会生成每个分片的 MD5，全文件在上传结束前计算首 1MB + 尾 1MB + 全文件 SHA-256。当哈希碰撞时，系统采用符号链接引用，跳过 Telegram 端物理上传流程，直接完成控制面注册，大幅节省 Telegram 上传带宽及耗时。

### 6.2 PWA & Service Worker 离线网络拦截
编写 `sw.js` 缓存 Web 界面静态资产（JS/CSS/SVG），并在网络故障时优雅展示离线备用提示：

```javascript
// sw.js
const CACHE_NAME = 'tg-drive-v4';
const ASSETS = [
  '/',
  '/assets/admin.css',
  '/assets/notifications.js',
  '/assets/upload-drop.js',
  '/assets/keyboard.js'
];

self.addEventListener('install', event => {
  event.waitUntil(
    caches.open(CACHE_NAME).then(cache => cache.addAll(ASSETS))
  );
});

self.addEventListener('fetch', event => {
  event.respondWith(
    caches.match(event.request).then(response => {
      return response || fetch(event.request).catch(() => caches.match('/offline.html'));
    })
  );
});
```

## 8. 旧产物清理与收尾清单

在升级为 v4.0.0-python 规划后，开发团队必须严格遵守以下物理文件清理规则，保障代码库免于技术债务堆积：

1. **废弃 Rust Tauri 模块**:
   - `app/src-tauri/` 目录中涉及 Rust 遗留 Tauri 的逻辑已不符合当前 Web+Python 后端的部署蓝图，全部归档至仓库外部备份，或直接在构建流程中 prune。
2. **废弃 React UI 残留**:
   - 清除 `app/src`、`app/package.json` 等 React 开发脚手架，以防非专业开发人员误将 Web 静态目录与 React 资产混淆。
3. **冗余脚本清理**:
   - 删除根目录下所有非 Python 的 `.sh` 文件（仅保留用于 Windows 的 powershell 脚本或 node hooks）。
   - 彻底删除 `x.tmp` 等临时性调试文件及旧版本的 `test_ledger.md`。
